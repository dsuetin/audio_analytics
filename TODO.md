## P0 (критичные — качество клиентских миссий с покупкой)

Приоритет внутри P0:
1. **recall реальных покупок** (каждая GT-продажа найдена как клиентская миссия);
2. **корректное выделение миссии, в которой была покупка** (не сдвинута/не обрублена);
3. **отсутствие ложного объединения** нескольких покупателей в один диалог;
4. **правильное определение `is_sale`**.

- [ ] **Построить корректное сопоставление GT-продаж с клиентскими миссиями (08-27).**
  Подход (без `client_id`): `store_id` + время продажи + содержание транскрипции →
  поиск клиентской миссии → проверка сегментации → проверка `is_sale`.
  Сопоставление **не** по `client_id` (это не источник истины).
- [ ] **Поднять recall реальных покупок при устойчивом precision** (не превращая все
  упоминания покупки в buy). Baseline 08-27: strict recall **0.325**, 39/80 NOT_FOUND,
  15 false-positive buy. NOT_FOUND — это в первую очередь **сегментация** (покупка не
  выделена как миссия): см. соседнюю задачу P0.
- [ ] **Не потерять реальную покупку внутри длинного customer dialog.**
  Симптом: отдельные диалоги 100–200+ минут, внутри — несколько клиентов/покупок/посещений
  (на 08-28/09-03 остаются >30 мин; max 09-03 ≈ 41 мин).
  **Нельзя** hard-cut по времени (например «разрезать по 60 минут») — время это **сигнал на
  LLM-review**, а не порог. Долгий сегмент НЕ считается автоматически одной миссией.
- [ ] **Корректные границы клиентской миссии: не объединять, не резать без причины.**
  При LLM-review использовать признаки:
  - завершение покупки (оплата/прощание) и начало новой встречи;
  - новое приветствие («здравствуйте», «добрый день»);
  - смена темы/товара, смена участника / `seller_id` (из raw-строк);
  - длинные паузы без речи;
  - семантическая связность (единая цель миссии).
  Измеримо: каждая GT-продажа 08-27 → ровно одна клиентская миссия; нет двух покупок в одной.
